# イナビカリ 見た目と素材

## 方針: 携帯ゲーム機風のドットで、AIっぽさを出さない

生成画像をそのまま使うと、細かすぎる描き込みやにじんだ色で「AIっぽさ」が出る。それを避けるため、次の3つに分ける。

| 種類 | 作り方 | 理由 |
|---|---|---|
| 歩く・走る選手（小さいドット） | コードの中に、ドットを1粒ずつ手打ちしたデータで持つ。体は共通、髪型・髪色・肌・ユニフォームを差し替え | 小さいドットは生成すると崩れやすい。手打ちなら本物のドット絵になり、容量もほぼゼロ |
| 会話の顔・カットインの顔 | 生成画像を取り込み、縮小・減色（16色前後）・輪郭線の整理をしてドット絵に変換 | 顔は描き込みが必要なので生成する。減色でゲーム機らしい見た目にそろう |
| マップのタイル・試合のピッチ | 小さいタイル（16×16 程度）の組み合わせ。コードの中に手打ちのドットで持つ | 生成画像はマス目にそろわないため。手打ちなら少ない素材で広い町を作れる |
| 必殺技の演出 | 画像を使わず、図形・粒子・光でコードが描く。ドットの解像度に合わせて描き、全体の見た目を崩さない | 一番力を入れる部分。数が増えても容量が増えない |
| 文字の窓・メニュー | コードで描く（ドット風の枠） | |

- 色は全体で使う色の表（パレット）を決め、全素材をその色に寄せる。これで、生成画像とコードで描いた絵がなじむ。
- 内部の解像度は低くし（例: 1画面 256×192 前後）、整数倍に拡大して表示する。ぼかさない。

## 必要な素材（見込み）

| 素材 | 数 | 作り方 |
|---|---|---|
| 顔（会話・必殺技のカットインで共用） | 36枚（31人＋主要3人の表情の追加5枚） | 生成→変換 |
| 歩くドット | 体の型 数種類（普通・大柄・小柄など）×4方向×歩き2〜3コマ | 手打ち |
| 町のタイル | 地面・建物・草・水・道など 数十種 | 手打ち |
| 背景の一枚絵（イベント用） | 5枚（河川敷・校舎前・夜の公園・開会式・決勝会場） | 生成→変換 |
| 表紙 | 1 | 生成 |

## 容量の見込み

- 顔: 1人 64×64 程度で16色なら1枚数KB。36枚まとめても 200KB 以下。
- 歩くドット・必殺技: コードの中なのでほぼゼロ。
- タイルと背景: 合わせて 1〜2MB 程度の見込み。
- 全体で 3MB 以下を目標にする。
